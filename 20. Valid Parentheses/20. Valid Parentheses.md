# Step1

- 3種類の括弧が正しく閉じているか判別する問題。
- stack を使う
    - 最後に出てきた開いた括弧を stack で管理
    - 閉じ括弧が出てきたときにそれと対応するか見ていく
    - 実装方法は list() しか思いつかない
- 括弧の対応関係は辞書型で管理

```python
class Solution:
    def isValid(self, s: str) -> bool:
        
        mappings = {"(" : ")", "[" : "]", "{" : "}"}
        last_words = []

        for char in s:
            if char in mappings.keys():
                last_words.append(char)
            elif last_words != [] and char is mappings[last_words[-1]]:
                last_words.pop()
            else:
                return False
        
        if last_words == []:
            return True
        
        return False
```

- 時間計算量：O(n)
- 空間計算量：O(n)
- 実装時の気になったこと
    - `==` , `in` を `is` に置き換えたら失敗した
        - `if char is mappings.keys():` がダメな理由
            - 型の違いとIDの不一致による
                - `==` ：値が同じかチェック
                - `in` ：その値が集合の中に存在するかチェック
                - `is` ：2つのオブジェクトがメモリ上の同じ場所にあるかをチェック
            - `char` という1文字のデータが、 `dict_keys` というリストのような構造体そのものと同じになることはない
        - `if last_words is []:` がダメな理由
            - リストは新しく作られるため
                - python において `[]` と書くと、実行されるたびに新しい空のリストオブジェクトが生成される
                    - `last_words is []`は`last_words` と、今新しく作った `[]` は、メモリ上の同じ住所に住んでいるか？を確認してしまう
    - `stack`  の実装方法は `list` 以外何があるか

| --- | --- | --- | --- | --- |
| **`list`** | 動的配列 (Dynamic Array) | $O(1)$ ※例外あり | × | インポートなしで手軽に書きたい時。途中の要素にもアクセスしたい時。 |

1. `list` （手軽だが、たまに遅くなる）

document▶https://docs.python.org/ja/3.13/library/stdtypes.html#list

Pythonのリストは「動的配列」として実装されています。

- **メリット:** 組み込みなので `import` 不要。`list[-1]` で一番上の要素を見るだけでなく、`list[0]` のように途中のデータも簡単に見られます。
- **デメリット:** メモリが一杯になると、裏側で「新しい広いメモリ領域を確保し、古いデータを丸ごとコピーする」という処理（リアロケーション）が走ります。そのため、普段は $O(1)$ ですが、**ごくたまに** $O(n)$ **の時間がかかってしまう**のが弱点です。

2. `collections.deque` （パフォーマンス最強）

document▶https://docs.python.org/ja/3.13/library/collections.html#deque-objects

`deque`（デック：Double-Ended Queue）は、両端から高速にデータの出し入れができるデータ構造です。

- **メリット:** 中身が「双方向連結リスト」のようになっているため、`list` のようなメモリの再確保（リアロケーション）が起きません。**データが何百万個になろうと、常に** $O(1)$**のスピードで `append()` と `pop()` が実行できます。**
- **デメリット:** リストの途中のデータにアクセスする（例：`deque[50]`）のは苦手で、 $O(n)$ の時間がかかります（スタックとして使う分には途中のデータは見ないので問題ありません）。

**【使い方】**

Python

```python
from collections import deque

stack = deque()
stack.append('a')  # Push
char = stack.pop() # Pop
```

3. `queue.LifoQueue` （マルチスレッド専用）

マルチスレッドプログラミング（複数の処理を同時に走らせる時）のためのスタックです。

document▶https://docs.python.org/ja/3.13/library/queue.html

- **メリット:** 複数のスレッドが同時にスタックを操作しても、データが壊れないように「ロック（排他制御）」がかけられます。
- **デメリット:** このロック処理が非常に重いため、今回のような単なるアルゴリズムの計算（単一スレッド）で使うと、**`list` や `deque` と比べて圧倒的に遅くなります。** 通常の用途では使いません。
    
    ---
    
    **まとめ：どれを選ぶべきか？**
    
    - **アルゴリズムの問題（LeetCodeなど）や、処理速度が求められるプログラム:**
        
        迷わず **`collections.deque`** をおすすめします。
        
    - **ちょっとしたスクリプトや、要素数が少ない・途中の要素も参照したい場合:**
        
        そのまま **`list`** で十分です。

    ```python
    class Solution:
        def isValid(self, s: str) -> bool:
            
            last_words = ["#"]
            mappings = {"(" : ")","{" : "}", "[" : "]"}
    
            for char in s:
                if char in mappings:
                    last_words.append(char)
                    continue
                
                if mappings.get(last_words[-1]) == char:
                    last_words.pop()
                    continue
    
                if char in mappings.values():
                    return False
    
            last_words.pop()
    
            if last_words:
                return False
    
            return True 
    ```
